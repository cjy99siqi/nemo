## 1. 这是什么

风电机组振动数据分析桌面工具：tkinter 单文件 GUI，批量读采集器导出的单通道 CSV，算特征指标入库做趋势，在谱图上标轴承/齿轮特征频率，最后套 Word 模板出月度报告。

- **输入**：CSV（无表头、单列加速度，`pd.read_csv(header=None).iloc[:,0]` `:826`），元数据全在**文件名**里（§4）；报告模板 `.docx`（默认 `数据\模板\田家寨项目报告模板.docx`）。
- **输出**：`vib_cache.db`（指标库）、`诊断关注清单.xlsx`、`输出\分析报告_<项目>_<起>_<止>_<戳>.docx`（`:5598`）。
- **不联网、无服务端**；一次运行 = 一个 tkinter 进程（`if __name__ == "__main__"` `:8234-8238`）。

## 4. 数据约定

### 4.1 文件名（元数据唯一来源）
标准式（`parse_filename :539`）：
```
<项目>_<机组>_<测点>_<采样率>Hz_<时长>s_加速度值_[<rpm>_]<14位时间戳>.csv
例：田家寨_101#_主轴承_前轴径向_20000Hz_10.00s_加速度值_1483_20250504090029.csv
```
- `加速度值` 是**字面量**，不是占位符；时长可为小数（`[\d\.]+`）；速率必须是整数 `\d+Hz`。
- 有/无 rpm 两分支；**时间戳必须正好 14 位**，多一段后缀（如 `_1`）即解析失败→该文件被静默跳过（`process_one_csv` 返回“测点名为空”）。
- 五峰式另两套：`<项目>_<机组>_<测点>_<fs>Hz_加速度_<rpm>_<14位>` / 无 rpm 版（`:510-538`）。
- 项目/机组段**不能含下划线**（`pre_str.split("_", 2)`，测点段可以含）。
- zip 导入会按规范格式**改名落地**（`:7002-7010`），时长按 `行数/fs` 反算（`:.2f`），故时间戳目录 `sub = target/<14位戳>`。

### 4.2 测点清单
`rule_text :187-202` 定义 11 个规范名（阈值/滤波带）：`主轴承_前轴径向`、`主轴承_后轴径向`、`主轴_前轴径向`、`主轴_后轴径向`、`齿轮箱_一级内齿圈径向`、`齿轮箱_中部径向`、`齿轮箱_高速轴径向`、`齿轮箱_高速轴轴向`、`发电机_前轴承径向`、`发电机_前轴承轴向`、`发电机_后轴承径向`。
`default_bp_text :205-226` 另补 11 个别名（`齿轮箱高速轴`、`齿轮箱输入端`、`齿轮箱一级齿圈`、`发电机前轴`、`发电机后轴`、`主轴轴承`、`齿轮箱_二级齿圈径向` 等），`:234-236` 以阈值 0 并入 → **`rule_dict` 共 22 个可识别测点名**。
README 说的“9 个测点”是现场实际使用子集，不是代码上限。测点不在 `rule_dict` → 该 CSV 直接被拒（`:822`）。

### 4.3 机组编号映射
`report_unit_label :4983`：`101#~125# → 1#~25#`，**仅在项目名含“府谷”或“田家寨”时**才减 100；其它项目原样输出。五峰机组号不带 `#` 也能用（`rstrip("#号")` + `int`）。
五峰另有采集异常黑名单 `WF_BAD_POINTS :125-135`（`wf_bad_point :138`）。**实测只有 `:2543` 一处调用**：命中时只是不自动标轴承特征频率，仍然照常入库、进趋势、进报告——想真正剔除得自己加过滤。

### 4.4 目录约定
- 「上传」选的就是 `main_dir`；`vib_cache.db`、`项目档案.json`、`vib_annotations.json`、`诊断关注清单.xlsx` 都落在这里。
- CSV 可在任意子目录，扫描用 `os.walk(main_dir)` 收 `.csv`（`:7191`）；孤儿记录按 `csv_set` 反删（`:7230`）。
- 多个项目目录可累加（`project_dirs`），树里合并显示（`:7046-7082`）。
- 转速缺失时可写入同目录 `vib_speeds.json`（`:4826`），阶次谱/表格复用。

## 5. 报告生成链路

1. **入口**：`VibGUI.open_report :6824` → `ReportDialog`；选项目目录 + 起止日期 + （可选）模板。
2. **取数**：`_go :5552` 开库 `db_connect(d)` → `db_load_all`，按 `dt_date` 过滤成 `picked`（`:5559-5571`）。**只读已入库数据**，没“计算数据”就没东西。
3. **汇总**：`report_stats(picked) :5004` → `agg[机组][测点] = {max, mean, n, ts, band, limit, ratio, grade, data_bad, peer_med}`。
   - `ratio = max / 第一限度`（`REPORT_VDI :4957`：低频 0.3、中频 7.5、高频 10.0）。
   - `report_grade :4969`：<80% 正常 / 80–100% 关注 / 100–200% 警告 / ≥200% 危险。
   - `vdi_only_normal`：主轴承/齿轮箱 `ratio≥0.8` 但无故障特征 → 改判“正常”（`:5038-5040`，`VDI_ONLY_PARTS :4955`）。
   - 数据异常：`max < 同型中位 × 0.05` → `data_bad`/“数据异常”（`DATA_BAD_RATIO :5062`）。
4. **故障判定**：`report_scan_faults :5167` 取每测点 RMS 最大的前 2 个 CSV → `report_env_peak :5118` 做包络谱（`report_env_curve :5092`，解调 1000–8000Hz、截 131072 点、汉宁窗）→ 与 BPFO/BPFI/BSF 基频 ±3% 比对，取最大幅值；阈值 `max(3.0, 5.0×同测点中位)`（`:5063-5064`）→ 命中写 `grade="警告"`（`report_apply_faults :5244`）。发电机测点按 `ge` 优先排序。
5. **选模板**：`profile_template :5292`（`项目档案.json` 的 `template.path`，失效回退 `backup`）；都没有就在 `数据\模板`、`模板`、`<项目>\模板`、程序目录里挑**最新 .docx**（`:5610-5624`）。
6. **填模板（有模板时，主路径）**：`importlib` 动态加载 `tpl_fill.py`（`:5626-5630`）→ `fill(tpl, out, project, d0, d1, agg, units, report_part_of, order, prof=…, rows=picked, fig_cb, caption_cb, analysis_cb)`。
   - 先 `shutil.copyfile(tpl,out)` 再 `Document(out)` —— **原地改人工模板，不动版式**。
   - 字段来源：数字全部来自 `agg`；日期/期次来自 `d0/d1`；`rows` 用于概述里的“记录时间/有效记录数”（`_fill_overview :137`）。
   - 表格定位靠**结构猜**：`_fill_units :201` 认“3 行×4 列的表 + 紧跟 12 行的 VDI 表”，机组号从 VDI 表首列纵向合并格正则取；`_fill_summary :233` 认表头含“主轴承/齿轮箱/发电机”的 6–7 列表。模板一改版式就可能**静默跳过**（`continue`）而不是报错。
   - 状态底色：`set_status :38` + `STATUS_FILL :9`（正常绿/数据异常灰/警告黄/危险红）。
   - 结论段：`_fill_conclusions :286` 靠“机组 N M#机组”向上回溯定位当前机组（`_current_unit_before :265`）。
7. **插图（关键）**：`_fault_blocks :315` 按段落标题 `N.3 诊断分析` … `N.5 处理建议` 切块，块内所有含 `w:drawing` 的段落即图片位。
   - `fig_cb` = `_figc`（`:5632`）：用 `report_fault_figure` 生成 `%TEMP%\repfig_<机组>.png`（上幅值谱 0–1000Hz、下包络谱 0–400Hz，dpi=200）。
   - `_replace_image :342`：先删该段所有 `w:drawing`，再 `run.add_picture(png, width=Cm(15.5))`（第二张 13.2，`IMG_WIDTHS :339`）。
   - 模板图多于本次图 → 连图带图注删除（`:382-394`）；整块无故障 → 整块删除（`:404-406`）。
   - `caption_cb` 重写“图N-1 …”，`analysis_cb` 重写“如图 N-1 所示…”。
   - 末尾 `_fix_lang :77` 把全文语言设 `en-US`+`zh-CN`，去掉 Word 中英文波浪线。
8. **无模板时**：`build_template_report :5866` 用 python-docx 从零画版式（A4、`黑体/宋体`、三级标题、VDI 表、故障页插 `fig_<N>.png` / `fig2_<N>.png`，`:6227` 建 `figs_<戳>\`）。
9. **收尾**：`os.startfile(path)` 打开；`collect_period/merge_period :5340/:5375` 写回 `项目档案.json`（保留 36 期，`PROFILE_MAX_PERIODS :5285`）。

## 6. 已知坑与注意点

1. **`启动振动分析.bat` 是 GBK（实测 58 字节，内容纯 ASCII + GBK 编码的中文文件名）**。用 UTF-8 另存后 cmd 按 936 代码页读会找不到 `振动分析.py`，双击闪退。改这个文件必须用 GBK/ANSI 存。
2. **`_bearing_dialog` 的“自定义倍数”是坏的**：`ok()` 里 `for _k,_v in v_cust.items()`（`:2660`）引用的 `v_cust` 只在 `_gear_dialog :2472` 定义，轴承对话框里根本没这组控件 → 点「确定」抛 `NameError`，标注不生效（Tk 只把 traceback 打到 stderr，pythonw 下完全静默）。要修就在 `_bearing_dialog` 里补 `v_cust` 输入框，或删掉 `:2659-2668`。
3. **`数据\` 里的轴承参数表在运行时根本没被读**：代码无 `read_excel`、无 `import xlrd`；`BEARING_LIB :78-112` 是硬编码。改 `明阳2.0MW.xlsx` / `运达各类型机组振动档案库.xls` 不会影响任何结果，要改倍数只能改代码。`xlrd>=2.0` 是历史遗留依赖（注意 xlrd 2.x 只能读 `.xls`，读 `.xlsx` 要用 openpyxl，两者不能互换）。
4. **滤波器 Nyquist 口径**：任何新滤波必须走 `design_band :472`（真实 `fs/2`）。历史上多处把 `fs/2.56` 当 Nyquist，导致截止频率偏大 1.28 倍、`Wn>=1` 时 scipy 抛 `ValueError`（“包络带通错误”弹窗）。`fs/2.56` 只用于**显示/分析上限**（`:394`、`:4199`）。
5. **改动计算口径必须同时 bump 版本号**：`VDI_VERSION=3 :292` 决定 SQLite 里的旧行是否重算，`DB_SCHEMA_VERSION=2 :69` 决定表结构。只改算法不改 `VDI_VERSION` → 老库照旧秒开、新算法不生效；库版本高于程序会直接抛“请升级程序”（`:718`）。
6. **中文显示**：matplotlib 只配了 `['SimHei','Microsoft YaHei']`（`:54`）且 `axes.unicode_minus=False`；信息面板另有 `family="SimSun"`（`:3228`、`:3909`）。缺字体 → 方框。改了字体名要删 `~/.matplotlib/fontlist-*.json` 缓存。docx 侧用 `黑体`/`宋体`（`build_template_report :5876`、`tpl_fill` 不改字体）。
7. **性能**：单文件 8238 行 / 400KB，全函数平铺，没有模块拆分；`SpectrumWindow` 一个类 3400+ 行、60+ 方法。改一处务必全文搜同名局部变量（`v_*`、`_r`、`_p` 这类短名在多个 `ok()` 闭包里重复）。
8. **大目录/大数据**：一个 CSV 常在几 MB～几十 MB，全量重算走 8 线程（`:7203`）+ 进度窗，窗口期间 `grab_set` 且禁止关闭（`:7182`）。异常必须落到 `state["error"]` 并置 `finished`，否则进度窗永远停在最后一个数字（`:7188` 有注释）。读 CSV 用 `pd.read_csv` 全量，几万文件时这是主要瓶颈。
9. **线程纪律**：工作线程不得碰 Tk；自相关/瀑布都走“主线程取信号 + 线程算 + `after` 轮询”（`:3912-3969`）。SQLite 连接按线程各开各的（`:7227`）。
10. **路径与编码**：全部 JSON 用 `encoding="utf-8"`；源码首行 `# -*- coding: utf-8 -*-`，文件无 BOM。新增文件读写请显式给 encoding，Windows 默认 GBK 会读写失败。
11. **`export_excel` 无入口**（`:8154`），`build_report_docx` 无调用（`:6410`），`trend_summary.json` 只读不写。别以为改它们会有效果。
12. **`parse_filename` 失败是静默的**（返回空 dict → 文件被跳过）。文件名对不上时先看 `load_all_files` 结束后的“部分数据未计算”弹窗（`:7263`），或手动跑 `parse_filename` 验证。
